# 使用者手冊

[English](user.md) | 繁體中文
> 本文為英文版的翻譯；內容不一致時，以英文版為準。

LevinRAG 只根據**你有權限閱讀的**公司文件回答問題，並在每一句話後面標出來源 `[n]`。資料裡找不到答案時，它會直接告訴你，不會自己猜。

以下用範例語料示範。alice 屬於 `all`、`hr` 群組，bob 屬於 `all`、`engineering` 群組。

## 登入

打開網站，輸入管理者給你的帳號與密碼。

- 登入後 8 小時內有效，時間到了需要重新登入。
- 按頁面上方的「登出」後，你在**所有裝置**上的登入都會一起失效。改密碼時也一樣。
- 帳號或密碼打錯時，畫面只會顯示「帳號或密碼錯誤」，不會告訴你是哪一個錯。

## 提問

在「問答」頁的輸入框輸入問題（最長 1000 字），按「送出」。回答通常需要 10–30 秒，這段時間會顯示「產生回答中…」。

例：alice 問「特休天數怎麼計算？」

> 特休天數依照年資計算，具體規則如下：
> - 到職滿 6 個月未滿 1 年：3 天 [1]
> - 滿 1 年未滿 2 年：7 天 [1]
> - …
>
> 來源
> [1] 請假規定　請假規定 > 特休 > 天數計算
> 　　（摘錄）… 開啟文件

- 回答中的 `[1]` 可以點擊，會捲動到下方「來源」的第 1 項並加上框線。
- 每個來源列出文件標題、章節路徑和一段摘錄；按「開啟文件」可以看原文。
- 只有回答實際引用到的來源才會列出。

## 看原文

「開啟文件」會打開文件檢視頁，並捲動到被引用的段落，該段以底色標出。

- 文件在建立索引之後若被修改過，頁面只會顯示「文件已更新，重新匯入後才能檢視。」，請管理者執行一次匯入。管理者看得到目前的檔案，並附提示「文件在建立索引後已變更，標示的位置可能不準確。」
- 你沒有權限的文件，無論是從網址直接打開還是從別處點進去，都只會看到「找不到頁面」。系統不會透露那份文件是否存在。

## 權限：同一個問題，不同人看到的不同

bob 問同樣的「特休天數怎麼計算？」時，`hr/` 底下的文件不會出現在他的來源裡，也不會被送給模型參考。這不是回答品質差，而是權限設計：

- bob 可能會得到依據公開文件（例如員工手冊）整理的較簡短回答，或是「在你有權限存取的資料中找不到相關內容。」
- 即使公開文件裡有一條連到 `hr/leave.md` 的連結，bob 點進去也只會看到「找不到頁面」。
- `hr/announcements/year-end-party.md`（尾牙公告）雖然放在 `hr/` 底下，但它自己開放給 `all` 群組，所以 bob 看得到。

如果你認為自己應該看得到某些文件，請找管理者確認你所屬的群組。

## 特殊訊息

| 畫面訊息 | 意思 |
|---|---|
| 在你有權限存取的資料中找不到相關內容。 | 沒有找到足夠相關的段落，所以系統沒有呼叫模型。換個說法、加上關鍵字（表單編號、料號）再試一次。 |
| 重排序失敗，結果依 RRF 排序。 | 排序模型暫時無法使用，答案仍然產生了，但來源的排序可能較差。 |
| 問答服務暫時無法使用（chat）。 trace … | 模型服務暫時無法使用。請把畫面上的 trace 編號提供給管理者，方便查詢原因。 |
| 模型沒有產生回答，請稍後再試。 | 模型回傳了空白內容。 |

## Debug 面板（進階）

勾選「送出」旁的 **Debug** 後再送出，回答下方會多出一張表，列出這次檢索的每一個候選段落。用它可以理解「為什麼是這幾段」：

| 欄位 | 意思 |
|---|---|
| chunk id | `文件路徑::段落序號` |
| lexical | 關鍵字比對的名次（「–」表示這個通道沒找到它） |
| semantic | 語意相似度的名次 |
| RRF | 融合兩個通道名次後的分數，越高越前面 |
| graph | ✓ 表示它是順著文件之間的連結被帶進來的 |
| rerank | 排序模型給的分數（原始 logit，可能為負；越高越相關） |
| 選中 | ✓（綠底）表示這段被放進給模型的資料 |

表格下方列出各階段耗時（ms）、使用的模型與 token 數；有 `flags` 或 `degraded` 時也會顯示。例如 `acl-starvation` 表示你能讀的文件太少，檢索結果被權限過濾後所剩不多。每一次提問都會留下紀錄（trace），Debug 面板上的數字與這筆紀錄一致。
